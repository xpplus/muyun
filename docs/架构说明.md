# 架构说明

## 分层

| 层 | 目录 | 职责 |
|---|---|---|
| 核心 | `core/` | `AppError` 统一错误、`Diag` 诊断日志、`Timeouts` 超时、`CrashGuard` 崩溃捕获 |
| 数据 | `data/` | `StoreRepository` 唯一持久化入口 |
| 云 | `cloud/` | `CloudProvider` 接口 + Instabox/Aliyun/Http 实现 |
| 功能 | `feature/` | ai / mcp / files / proxy / power / terminal |
| 界面 | `ui/`（待拆） | 屏幕与组件 |

## 关键约定

1. **错误**：业务层返回/抛出 `AppError`，UI 只展示 `userMessage()`，技术细节进 `Diag`
2. **日志**：统一 `Diag.i/w/e(category, msg)`，分类 + 级别 + 500 条环形缓冲 + 1 秒去重
3. **持久化**：只能通过 `StoreRepository`
4. **云厂商**：新增 = 新增一个 `CloudProvider` 实现 + 注册，不改主流程
5. **文件**：路径拼接统一 `PaneNav`；传输算法统一 `Transfer`
6. **AI 工具**：提示词 `AiPrompt`、动作解析 `AiCore`、工具清单 `McpTools` 三处对照

## 说明

分层职责见上文；`MainVm` 仍承担部分业务编排，后续如需继续拆分可参考各 `feature/` 模块的边界。
